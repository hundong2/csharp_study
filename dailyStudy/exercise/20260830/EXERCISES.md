# 단계별 실습

각 단계 뒤에 `dotnet build`와 `dotnet run -- --self-test`를 실행하세요. 한 번에 정답을 복사하기보다 작은 변경을 검증하는 습관이 목표입니다.

## 1단계: 기초 문법 확인

`RET-105` 요청을 추가하세요. 금액은 55,000원, 사유는 `change-of-mind`, 배송 후 7일, 미개봉으로 만들고 승인되는지 확인하세요.

## 2단계: nullable 경계 다루기

사유가 공백인 요청을 추가해 거절되는지 확인하세요. 왜 `ReasonCode`가 `string?`인지, null 검사 없이 `ToLowerInvariant()`를 부르면 어떤 문제가 생기는지 설명하세요.

## 3단계: Strategy 확장

`PremiumReturnPolicy`를 새로 구현해 VIP 고객은 단순 변심 기간을 30일로 늘리세요. 기존 `PlanReturnsService`는 수정하지 말고 Composition Root에서 구현만 교체하세요.

## 4단계: 실패와 테스트

같은 요청 ID에 다른 계획을 두 번 저장하면 `Result` 실패가 되는 자체 테스트를 추가하세요. 이어서 저장소가 예외를 던지는 테스트 대역을 만들어 예상된 업무 실패와 운영 장애의 차이를 확인하세요.

## 5단계: 실무 설계 토론

다음 질문을 각각 두 문장으로 답하세요.

1. 저장과 환불 이벤트 발행 사이 장애를 Outbox로 어떻게 막을까요?
2. 여러 상담원이 동시에 처리할 때 `ExpectedVersion`은 무엇을 검출할까요?
3. 로그에 주문 ID나 주소 원문을 남기면 어떤 위험이 있을까요?
