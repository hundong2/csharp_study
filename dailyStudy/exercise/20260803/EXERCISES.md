# 실습 문제

## 1단계: 초보자 검증

1. `dotnet run`을 실행하고 만료·유지 건수를 적어 보세요.
2. 두 예약의 `CreatedAt`, `ExpiresAt`, `Status`가 어떤 값인지 말로 설명하세요.
3. `BatchSize`를 `0`으로 바꾸고 Result 실패 메시지를 확인하세요.

## 2단계: 직접 수정

1. 정확히 만료 시각과 같은 예약이 만료되는지 self-test를 하나 추가하세요.
2. 고객 ID가 `vip-`로 시작하면 15분 연장하는 `VipExpiryPolicy`를 구현하세요.
3. LINQ 결과에서 가장 오래된 예약이 먼저 오는 이유를 설명하세요.

## 3단계: 실무 확장

1. 같은 예약을 두 작업자가 처리할 때 생기는 문제와 낙관적 동시성 해결책을 적으세요.
2. 만료 이벤트를 안전하게 발행하기 위한 Outbox 흐름을 설계하세요.
3. Repository가 한 번 실패한 뒤 성공하는 가짜 구현을 만들고 예외 흐름을 검증하세요.

힌트: 우선 실패하는 테스트를 만든 뒤 최소 코드로 통과시키세요. 정책은 Application Service에 `if`를 늘리기보다 Strategy 구현으로 추가해 보세요.
