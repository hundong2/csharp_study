# 실습 과제

## 1단계: 초보 검증

1. `DSP-101`의 금액을 `99_999m`으로 바꾸고 결정이 왜 달라지는지 말해 보세요.
2. `ReasonCode`가 `null`인 건이 왜 거절되는지 해당 `if` 조건을 말로 설명하세요.
3. `dotnet run -- --self-test`가 4/4인지 확인하세요.

## 2단계: 문법 연습

- `TriageSummary`에 `TotalCount` 속성을 LINQ로 추가하고 출력하세요.
- `service_not_received` 사유를 일반 검토로 처리하는 `switch` 식 패턴을 추가하세요.

## 3단계: 설계 연습

- VIP 거래는 50,000원부터 긴급 검토하는 새 Strategy를 구현하세요. 기존 서비스를 수정하지 않는 것이 목표입니다.
- 저장소가 같은 분쟁 ID에 다른 결과를 저장할 때 실패하는 테스트를 추가하세요.

## 4단계: 실무 확장

- 결제 참조 원문을 로그에 남기지 않으면서 상관관계 ID와 정책 버전을 감사 로그에 추가하세요.
- 실제 DB와 메시지 브로커를 쓴다면 낙관적 동시성, 트랜잭션, Outbox를 어느 경계에 적용할지 그림으로 설명하세요.
