# 단계별 실습

각 단계 뒤에 `dotnet build`와 `dotnet run -- --self-test`를 실행하세요. 한 번에 정답을 복사하기보다 작은 변경을 검증하는 습관이 목표입니다.

## 1단계: 기초 문법 확인

`REQ-105` 요청을 추가하세요. `WELCOME`, 가입 20일, 마케팅 동의 상태로 만들고 발급되는지 확인하세요.

## 2단계: nullable 경계 다루기

등급이 null인 LOYALTY 요청을 추가해 예외 없이 처리되는지 확인하세요. 왜 `Grade`가 `string?`인지, `?.` 없이 `ToUpperInvariant()`를 부르면 어떤 문제가 생기는지 설명하세요.

## 3단계: Strategy 확장

`HolidayCouponPolicy`를 구현해 구매액 50,000원 이상 고객에게 시즌 쿠폰을 발급하세요. 기존 `IssueCouponsService`는 수정하지 말고 Composition Root에서 구현만 교체하세요.

## 4단계: 실패와 테스트

같은 요청 ID에 다른 계획을 두 번 저장하면 `Result` 실패가 되는 자체 테스트를 추가하세요. 이어서 저장소가 예외를 던지는 테스트 대역을 만들어 예상된 업무 실패와 운영 장애의 차이를 확인하세요.

## 5단계: 실무 설계 토론

다음 질문을 각각 두 문장으로 답하세요.

1. 계획 저장과 실제 쿠폰 발급 사이 장애를 Outbox로 어떻게 막을까요?
2. 여러 작업자가 동시에 처리할 때 `ExpectedVersion`은 무엇을 검출할까요?
3. 로그에 고객 ID나 구매 내역 원문을 남기면 어떤 위험이 있을까요?
