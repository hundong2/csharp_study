# 실습

## 1단계: 초보 검증

코드를 바꾸기 전에 다음 값을 손으로 계산하세요.

- `COUNT-101`의 차이는 `실사 수량 - 장부 수량`으로 얼마인가요?
- `COUNT-102`는 어떤 결정이어야 하나요?
- `COUNT-103`이 자동 조정되지 않는 이유는 무엇인가요?
- 빈 SKU가 왜 경계에서 거절되어야 하나요?

그다음 `dotnet run` 결과와 비교하세요. 예상이 다르면 `difference`, `if`, `enum` 설명을 다시 읽습니다.

## 2단계: 기본 문법 수정

자동 조정 한도를 5에서 3으로 바꾸고 실행 결과가 어떻게 달라지는지 설명하세요. 이어서 음수 수량 데이터를 하나 추가해 거절되는지 확인하세요.

## 3단계: 정책 확장

차이율이 10%를 넘으면 수량 차이가 작아도 수동 검토하는 `PercentageReconciliationPolicy`를 만드세요. 기존 서비스는 수정하지 말고 Composition Root에서 구현만 교체합니다. 이것이 Strategy와 OCP인 이유를 적으세요.

## 4단계: 저장 충돌

메모리 저장소가 같은 `CountId`이지만 다른 `ExpectedVersion`의 결과를 받으면 실패하도록 테스트를 추가하세요. 실무 DB에서는 `UPDATE ... WHERE Version = @expectedVersion`의 영향 행 수가 0일 때 동시성 충돌로 판단할 수 있습니다.

## 5단계: 운영 설계

재고 조정과 감사 이벤트 발행 사이에 프로세스가 종료되는 상황을 그려 보고 Outbox가 필요한 이유를 3문장으로 정리하세요. 로그·메트릭·알람 각각에 무엇을 남길지도 적으세요.
