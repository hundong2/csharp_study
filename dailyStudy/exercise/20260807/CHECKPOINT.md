# 초보자 체크포인트

## 코드 읽기 질문

1. `FailedJob`은 데이터인가, 작업 순서를 담당하는가?
2. `ExponentialRetryPolicy`를 바꿔도 저장소가 영향받지 않는 이유는 무엇인가?
3. `ProcessFailedJobsService`가 구체 클래스 대신 인터페이스를 받는 이유는 무엇인가?
4. `ToArray()`를 빼면 LINQ가 언제 실행될 수 있는가?
5. 취소 예외를 일반 실패로 감추면 운영 종료 때 어떤 문제가 생길 수 있는가?

## 답 확인

1. 업무 데이터를 표현하는 Domain Model입니다.
2. Strategy 계약 뒤에 규칙을 격리했기 때문입니다.
3. 구현 교체와 단위 테스트가 쉬워지는 의존성 주입/DIP 구조이기 때문입니다.
4. 실제 열거가 시작될 때 지연 실행될 수 있습니다.
5. 호출자가 취소와 장애를 구분하지 못해 불필요한 재시도나 느린 종료가 생길 수 있습니다.

## 최소 완료 기준

- 일반 실행과 self-test가 모두 성공한다.
- `Result`와 예외의 사용 기준을 한 문장으로 설명한다.
- Repository, Strategy, Application Service, Composition Root를 코드에서 각각 찾는다.
- 재시도 전에 멱등성이 필요한 이유를 설명한다.
